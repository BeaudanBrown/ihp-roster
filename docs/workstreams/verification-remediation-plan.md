# Verification remediation acceptance design

Proposed cross-cutting design for
[#580](https://github.com/BeaudanBrown/ihp-roster/issues/580) in
[epic #576](https://github.com/BeaudanBrown/ihp-roster/issues/576).
The issue owns measured ranking, proposed implementation slices, dependencies
and selection. No performance implementation or gate-policy change is authorized
by this document. Detailed owner designs remain in the
[compiler](verification-compiler-evidence.md) and
[runtime](verification-runtime-iteration.md) workstreams.

## Implementation shape

Prefer independently reversible owner refactors to a new global verification
scheduler. Prove one owner's complete result before reusing it elsewhere.
Establish measurement and safety fixtures first; optional browser completion
and static compiler evidence can then be implemented independently. Schedule
runtime groups only after removing avoidable waits, since their weights change.
Defer a cross-owner DAG until producer identities and publication are proven.

The first evidence module should belong to strict warnings, behind a small
interface that resolves inputs, validates/recomputes evidence and returns the
original owner's result. Callers must not orchestrate lock, hash, publish and
cleanup operations themselves. Extract shared mechanics only when a second
real owner needs them. Weeder analysis, generated proofs and executables require
different manifests and success conditions; avoid one permissive generic cache.

## Evidence ownership and publication contracts

| Proposed owner | Result it may reuse | Additional identity and authority |
|---|---|---|
| Strict warnings | Complete strict success for the inventoried owned subjects | Warning policy and ownership exclusions; dependency-interface preparation is not strict success |
| Generated proof validation | Complete validation of freshly resolved generated modules and private proofs | Generator/formatter identity, stable logical paths, output bytes, exact managed-output set and all proof subjects |
| Negative fixtures | At most dependencies initially, not fixture outcomes | Every required fixture retains attributed expected/rejected diagnostics; compiler failure alone is not success |
| Weeder analysis | Canonical analysis or advisory, independently | Completed complete HIE sweep, exact source/HIE sets and bytes, root/baseline policy, tool/analysis identity; advisory provenance never becomes gate authority |
| E2E executable producer | Immutable app/worker/mock binaries | Full linked source/object/package/native-library/toolchain closure and flags; no runtime/test success reuse |
| Runtime owners | No static certificate for tests | Fresh isolated execution with unchanged suite/device selection, retries and cleanup contracts |

Each versioned manifest must identify purpose, platform, compiler executable,
package DB/unit IDs and native dependencies, effective options and include/CPP/
plugin inputs, relevant environment, scripts and policy; plus sorted source paths
and contents, inventories, additions/deletions and generated/untracked inputs.
HEAD or a Git diff hash is provenance, not content-complete identity. Use
workspace scoping initially; cross-worktree sharing needs separate trust review.

Resolve generation before capturing inputs. Include actual generated bytes,
schema/compiler/formatter inputs and TH file dependencies. Audit untracked file,
environment or external reads; if the dependency closure is unknown, recompute
rather than certifying it. Hashing all tracked files both misses ignored inputs
and invalidates unnecessarily on prose; narrow only after mutation tests prove
which inputs affect each owner.

Use immutable input snapshots, or an equivalent locked producer protocol that
prevents transient edit-and-restore races. A final hash recheck alone is not
sufficient. Under a workspace/purpose/key lock: recheck for complete evidence,
build into private staging, verify all required outputs, then publish an atomic
manifest referencing immutable outputs. A reader validates identity, integrity
and completeness. No caller may interpret a precompile stamp as completion.

Corruption, a missing artifact or incompatible manifest means a cache miss and
normal recomputation. A real compiler/test failure still fails; do not rerun it
until it passes or hide it behind fallback. Kills, timeouts and partial writes
publish no success. In shadow mode a cached/uncached discrepancy fails acceptance
and disables reuse. Preserve unrelated completed keys without labelling them
current. Diagnostics distinguish miss, invalid evidence, lock wait, producer
failure and successful reuse.

## Concurrency and resource contracts

Keep one environment entry at a time and one writer per mutable compiler graph.
Generation, graph preparation and publication need a documented lock order;
never wait for an upstream generation lock while holding a downstream output
lock that its producer needs. Same-key contenders wait and recheck; distinct
keys must not share writable artifacts. Cancellation must release locks and
reap owned descendants without deleting another producer's staging area.

Only after serial isolation is proven, experiment with two strict-warning
workers, private copied/reflinked interfaces/objects/temp roots and frozen
inputs. Cap GHC jobs and RTS capabilities explicitly; worker count does not
bound an inherited unbounded compiler job option. A combined 4 GiB experimental
ceiling is a starting abort limit, not a demonstrated safe production default.
Record aggregate process-tree/cgroup peaks, not a sum of independently observed
RSS maxima. Exceeding the limit fails the experiment without publishing evidence;
resizing requires new measurements. Keep a known-good serial route.

Browser/Hspec scheduling changes assign whole independently isolated groups,
not concurrent examples sharing fixtures. Calculator batching owns one private
profile and closes documents between cases, with both document and batch
watchdogs. DB rollback experiments must prove single-connection ownership and
absence of committed observers; otherwise retain the reset owner. Refer to the
runtime workstream for the adversarial cases and immutable executable protocol.

## Guarantee-to-regression matrix

Tests must cross the same owner interface used by canonical commands. A hash
unit test alone cannot prove that a failing compiler/proof is never skipped.

| Change/state | Required observation and authority |
|---|---|
| Empty owner output, retained package cache | Complete producer executes; original warning/proof/test results and required subject inventory preserved |
| Immediate unchanged warm repeat | Only eligible static owners hit; runtime tests remain fresh; cached and uncached results agree |
| Owned Haskell or transitive dependency edit | Relevant certificate misses and introduced warning/error fails; unaffected owners may hit only with proven disjoint closure |
| Schema or schema-generator change | Generated outputs refresh before identity capture; affected compiler/proof/executable evidence misses; schema/migration checks remain required |
| Authored frontend, generated TS or static asset edit | Correct generator/typecheck/build/browser/package owners invalidate; no runtime skip based on unchanged Haskell |
| Docs-only edit | Proven unrelated compiler owners retain evidence; documentation authorities still execute and fail on broken references |
| Tooling script, formatter, generator or policy edit | Affected producer misses; tool-only production exclusion is independently checked |
| Generated/ignored/untracked input changes | Bytes and membership enter relevant identity; incomplete or unknown dependencies force recomputation |
| Add, rename or delete source/output | Exact subject and output sets invalidate; missing owned subjects, managed proofs and stale HIE cannot pass |
| Warning policy or compiler/package/platform drift | Miss even at the same numeric GHC version; all strict warning and instance/generated-exclusion fixtures retained |
| Negative fixture altered, missing or unexpectedly compiling | Complete fixture membership and attributed diagnostics enforced; dependencies cannot certify fixture outcomes |
| Root/baseline/advisory policy drift | Complete HIE validation and independent canonical/advisory invalidation; narrow roots and conservative provenance preserved |
| Failure, kill, interrupted publish, corrupt manifest/output | No partial success; reader recomputes or fails explicitly; real failure never becomes a hit |
| Concurrent agents, same/different keys | Serial same-key publication, isolated other writers, no mixed-generation result, deadlock or foreign cleanup |
| Runtime scheduling/login/executable changes | Exact test/project identity sets and retry truth; delayed/missing readiness, stale auth, live acknowledgement/resync and process cleanup fixtures pass |
| Calculator batching | Real formula/value and save/reopen checks, one cold start, contaminated/hung/invalid document cases and watchdog cleanup |
| Reset/transaction refactor | Manifest completeness, sequence state, cross-example/venue leakage, pooled connections and committed observers remain protected |
| Production/package boundary change | Reviewed closure/dependency/executable inventories, tooling exclusion, artifact/size limits and all executable smoke checks remain independent |
| Fast then full | Focused/fast feedback never substitutes for complete Hspec/browser/device/package/schema/migration/billing/deployment authority |

## Repeatable acceptance budgets

These are proposed acceptance criteria, not claims that existing observations
meet them. Establish a successful matched control after resolving infrastructure
and production prerequisites; never compare a passing candidate with a truncated
failed pipeline as a speedup. Follow `docs/runbooks/performance-profiling.md`.

- Pin host/toolchain, source class, tier, project/shard selection, cache state and
  builder/network policy. Record host pressure. Use command-only monotonic
  timers with setup/teardown phases separated; per-command CPU deltas and
  process-tree/cgroup peak memory. Retain all attempts and interruption reasons.
- Collect at least seven matched successful control/candidate pairs for warm
  states, alternating order; three independent supported output-cold pairs.
  Retain package/Nix/OS caches unless separately approved. Report median and
  observed maximum as the small-sample tail, with sample count; do not call it
  p95. Percentile claims need a separately sized repeated experiment.
- Benefit acceptance: targeted owner median improves by at least the larger of
  5% or one second, beyond observed run-to-run noise, without guarantee loss.
  Static-warning unchanged-hit goal: median at most ten seconds including
  identity validation. This is a design target requiring measurement, not a
  promised speedup. Reject or redesign a refactor whose overhead erases benefit.
- Non-regression: matched complete fast/full medians must not worsen by more
  than 5%, and observed maxima by more than 10%; affected miss/output-cold owner
  paths get the same relative limits with a one-second measurement allowance.
  Repeated contention requires a new labelled cohort, not selective exclusions.
- Memory: comparable aggregate peak must remain within the larger of 10% or
  128 MiB above control, as well as explicit experiment/host headroom limits.
  Parallelism exceeding that budget needs operator-approved evidence and revised
  limits, not silent acceptance. No production durability or test selection
  change may be used to satisfy a performance target.
- Required gates must all pass, with no new retries/flakes, suppressed failures,
  skipped tests or reduced device/fixture membership. If a control flakes,
  record the failure and resolve/classify it before claiming clean acceptance;
  collecting successful pairs does not erase failed attempts.

## Rollout, rollback and prerequisites

For each independently committed slice: add adversarial fixtures and timing,
prove serial/cold behavior, compare uncached and candidate results in shadow
mode, then opt in locally. Enable default reuse only after mutation/concurrency
coverage and matched performance acceptance pass. Keep a documented uncached
route and a versioned manifest namespace so rollback ignores new evidence.
For runtime refactors, retain a reversible owner change rather than adding
permanent alternative behavior throughout tests.

On mismatch, stop publication, preserve logs/keys, disable reuse and run the
original owner. Revert the specific behavior commit while keeping useful tests
and diagnostics where possible. Never wipe shared caches/databases as rollback;
only owner-scoped disposable state may be removed through its lifecycle. The
new gate is not release authority until all required checks pass.

Production closure/budget reconciliation, remote-builder health and stable
measurement conditions are prerequisites to complete-pipeline acceptance, not
performance shortcuts. They require independent reviewed changes or explicit
labelled local-builder policy; do not silently raise budgets or disable builders.
Unsafe reset eligibility, precise per-process readiness attribution and parallel
compiler memory feasibility remain proof obligations, not assumed savings.
Per-subject warning invalidation and a cross-owner DAG should follow conservative
owner-local reuse; they have larger correctness surfaces and unproven benefit.

Affected living owners: `Config/nix/README.md`, `e2e/AGENTS.md`, `Test/AGENTS.md`
and `docs/runbooks/performance-profiling.md`. Move proven contracts there as
approved slices land, then retire unresolved workstreams rather than maintaining
a second task tracker. Creating/selecting implementation issues, epic closure,
synchronization/integration and cleanup remain separate approval boundaries.
