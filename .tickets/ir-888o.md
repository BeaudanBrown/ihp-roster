# Generated FrontendSurface interaction render helpers and surface polish

Design and implement generated/SurfaceImpl-backed interaction render helpers, then clean remaining surface naming and documentation polish.

## Design

FrontendSurface remains the source of truth for surface topology, actions, intents, interaction sessions, effects, conflict policies, scopes, and live fragments. Current low-level data-bepis-* marker helpers stay as internal browser-contract render primitives, but feature views should migrate to typed FrontendSurface-aware render helpers. The work should preserve the current browser runtime and avoid reintroducing LiveSurface compatibility. Naming/doc polish should happen after migration so tests, guardrails, and living docs use Surface/FrontendSurface vocabulary consistently.

## Acceptance Criteria

Feature views no longer hand-wire interaction data-bepis-* markers where a generated/SurfaceImpl-backed helper exists; generated interaction helper API is documented and covered by tests; low-level marker helpers are internal/shared primitives with guardrails against broad feature use; remaining non-archive docs/tests use current Surface/FrontendSurface naming; verification passes.
