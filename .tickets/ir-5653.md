# Persist and assign shift type colour keys

Add a persisted colour key for shift types and automatic assignment/reassignment rules for active shift types.

## Design

Add a shift_types colour field such as colour_key/color_key with a CHECK limiting values to ten palette keys plus default. Backfill existing venue shift types by active display order: first ten active types receive distinct palette keys, overflow and inactive/defaultable rows receive the reusable default unless preserving a non-colliding stored key is simpler during migration. Update generated types after schema change. Centralize the palette and assignment helper so create/reactivate paths choose the first unused palette key among active shift types for the venue, falling back to default. If an inactive shift type is reactivated with a key already used by another active shift type, reassign before save. Reordering should not reshuffle existing colours.

## Acceptance Criteria

Application/Schema.sql includes the colour key field and constraints. Generated types are refreshed. Create and reactivation/update mutation paths assign first-available colours and default overflow. Active shift types do not share non-default palette keys within a venue through supported mutations. Tests cover create overflow and reactivation collision reassignment.
