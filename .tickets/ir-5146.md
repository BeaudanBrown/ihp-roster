# Simplify frontend contract architecture around Surface and AppShell primitives

Converge frontend request ownership on FrontendSurface for durable feature content and AppShellAction for app shell, global dialog/toast/chrome, and other non-feature-surface request initiators. Remove OverlayAction as a separate primitive, retire stale temporary roots, migrate remaining raw request-side HTMX, and tighten guardrails.

## Design

AppContract remains the base vocabulary root for app-wide DOM ids/events/closed values. AppShellContract owns app-shell request initiators and references AppContract DOM ids such as DialogOverlayMount rather than redeclaring them. FrontendSurface owns durable feature content, fragments, actions, live resources, mount state, and interaction semantics. Generated HTMX metadata is represented by one shared IR/rendering model used by Surface and AppShell actions. OverlayAction becomes an AppShell dialog-lane action category during migration, then is removed. Broader risky contract reshaping such as InteractionContract is gated by an audit/planning ticket that stops for user approval before follow-up implementation.

## Acceptance Criteria

RegisteredFrontendContracts removes OverlayContract and RosterGlobalContract; AppShellContract exists and generates typed action manifests/runtime helpers; Surface and AppShell request actions share deduplicated HTMX metadata IR/rendering; current overlay/dialog actions are migrated to AppShell and production OverlayAction imports/helpers are removed; remaining app-owned raw request-side hx-* in Haskell views/helpers is migrated or explicitly exempted as generated runtime/response-only/test behavior; StaffSurface exists for manager staff editing with shared staff/profile definitions; guardrails enforce final architecture; planning-gate tickets stop for user approval before broader InteractionContract reshaping.
