# Migrate roster interaction views to generated helpers

Replace manual interaction marker wiring in roster views with the new FrontendSurface-aware helpers.

## Design

Roster is the primary complex consumer of typed interaction surfaces. Migrate one coherent slice at a time while preserving DOM contracts used by frontend tests and e2e coverage.

## Acceptance Criteria

Roster views use generated helper APIs for drag/drop, activation, disposable layer, and intent form wiring where available; existing interaction runtime and roster tests pass; direct low-level marker imports are reduced or eliminated from roster feature views.
