# Build guided Xero draft-timesheet preparation modal

Replace the separate Xero payroll readiness chores with a single panel-instigated workflow modal. The modal prepares draft timesheets for a user-selected Xero pay period, automatically runs deterministic checks/actions, pauses only for required user decisions, shows a preview, then requires explicit confirmation before draft submission.

## Design

Entry point remains in the Xero admin timesheet panel. The panel offers a Xero pay-period selector populated from synced payroll calendars/pay runs and one primary Prepare action that opens an HTMX workflow dialog in the shared dialog overlay mount.

The selected period option is the source of truth for the payroll calendar/window used by preparation, readiness, preview, duplicate checks, and submission. Modal preparation must not require the venue-global `xero_payroll_calendar_selections` row. Xero remains source of truth for employee calendar membership via synced `xero_employees.payroll_calendar_id`; the app must not ask users to assign staff to calendars locally.

Preparation is an application-level orchestration flow, not controller glue. OAuth reconnect remains native full-page when required. Reference sync, selected-period validation, pay-run status checks, remote timesheet duplicate checks, pay-item readiness, and readiness validation should advance automatically when no user choice is required.

Staff matching happens in the modal as a decision queue. Proposed auto-matches require approval before persisting. Manual staff mapping is allowed through dropdown controls in the modal, but there is no separate match button. Staff can be marked not paid through Xero persistently. Run-scoped skip is allowed only for currently unmapped staff. Staff mapped to Xero employees on a different synced payroll calendar are excluded from the selected submission with a warning, not blocked by local calendar assignment.

Managed pay items that need creation require approval in the same modal. Existing remote Xero timesheets block create in v1. Posted pay runs hard-block the selected period. Advanced/debug detail may remain available, but the primary UI is a guided Prepare -> resolve decisions -> preview -> confirm submit flow rather than accordion chores.

## Acceptance Criteria

Venue owner/super-admin can select a Xero pay period and complete preparation through the modal without visiting separate readiness/mapping sections. The modal works without `xero_payroll_calendar_selections`, uses the selected Xero period calendar/window throughout, excludes different-calendar employees with a clear warning, supports proposed/manual/not-paid/skip staff decisions as defined above, reaches a deterministic preview only after blockers are resolved, and submits draft timesheets only after explicit preview confirmation. Modal uses shared overlay patterns and is covered by focused Xero Hspec plus at least one E2E workflow.
