# Introduce admin config section mutation helpers

Extract a shared helper pattern for admin config HTMX/live-fragment mutation responses after the Xero/admin boundary split.

## Design

The scan found repeated admin patterns: validate mutation, reload a section,
return an HTMX fragment for the actor, emit toast OOB markup, and broadcast the
matching live scope for other open pages. Introduce a small helper after the
Xero boundary split so admin sections have one response shape.

Candidate shape:

- a config record carrying section name, target id, fragment action/url,
  renderer, success/error toast text, and live scopes to invalidate.
- helper functions for success, validation failure, and not-found/forbidden
  responses.
- support for actor-local HTMX fragments plus optional full-page redirect
  fallback.

Initial adoption targets:

- admin invites
- roster groups
- slot names
- shift types
- Xero sections only after `ir-23k7` has made their boundaries stable

Guardrails:

- Do not convert low-frequency session/security flows to HTMX just to use this
  helper.
- Keep section-specific validation and domain mutation in section modules; this
  helper should own response plumbing only.
- Preserve existing fragment ids and toast text unless tests are updated for an
  intentional copy change.

## Acceptance Criteria

- At least two admin config sections use the shared mutation response helper.
- Actor HTMX responses still update the expected section and toast mount.
- Other open tabs/users still resync through the same live scopes.
- The helper is documented by call-site examples rather than hidden behind a
  broad abstraction with many optional fields.
