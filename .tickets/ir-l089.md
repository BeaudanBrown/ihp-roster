# Clarify roster multi-preference conflict semantics in direct SQL path

Direct conflict SQL treats a shift as matching if any same-day staff preference window contains the start time, while the existing Haskell conflict helper checks only the first same-day preference. Decide and align the implemented behavior so projection/direct parity is meaningful.

## Design

Inspect existing product intent and tests around multiple staff_shift_preferences for a weekday. Either change the direct SQL to match the existing first-preference semantics, or update the shared Haskell helper/specs to the intended any-window semantics. Add an explicit test with multiple same-day preferences where one matches and one does not.

## Acceptance Criteria

Multiple same-day preference windows have an explicit tested behavior. Direct SQL conflicts and the shared Haskell conflict helper agree for that case. Focused conflict/roster tests and typecheck pass.
