# Replace roster profiling spine with OpenTelemetry

Move the request/render profiling spine from custom Server-Timing and X-Profile-Counters headers to OpenTelemetry traces and low-cardinality metrics while preserving roster-specific HTML/render diagnostics and giving coding agents first-class access to profile results.

## Design

Adopt OpenTelemetry with Grafana Tempo/Grafana/Prometheus-compatible metrics as the preferred backend. Keep IHP_ROSTER_OTEL separate from IHP_ROSTER_PROFILING: OTel request tracing should be safe for staged/prod sampled use, while heavier HTML pre-render/component byte profiling remains diagnostic-only. Bridge existing profileActionSpan/profileHtmlComponent/profileCounter semantics into OTel spans, span attributes/events, and eventually metrics instead of deleting the semantic instrumentation. Avoid PII: no names, emails, raw query strings, or high-cardinality staff/slot/user labels by default. Provide agent access first through profile artifacts and a project Pi extension, with Grafana MCP as the richer backend integration once Grafana/Tempo is available.

## Acceptance Criteria

Requests produce useful OTel root and child traces; roster render spans expose component duration/bytes and request-shape counters; stable low-cardinality metrics are available for response/component bytes and render durations; local/profile runs produce agent-readable OTel summaries; coding agents can run a low-rate profile and query/compare results through tools; custom X-Profile-Counters are deprecated or compatibility-only; existing profiling remains default-off and production-safe.
