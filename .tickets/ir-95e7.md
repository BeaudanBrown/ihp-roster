# Generate TypeScript contracts for typed interaction capabilities

Extend Haskell-owned frontend contract generation so TypeScript consumes interaction surface, disposable layer, intent, field-schema, session, and conflict-policy types from Haskell definitions.

## Design

Plan update: `ir-libm` now tracks folding the temporary `ir-fq28` wrapper shape back into the canonical `TypedLiveSurfaceDefinition` before render helpers/runtime work depend on it. This contract-generation slice still emits the browser-boundary DTO vocabulary from Haskell-owned interaction declarations.

Extend the existing contract generation path (`Application.Helper.Frontend.Contracts`, `Application.Script.GenerateFrontendContracts`, `frontend/ts/generated/contracts.ts`). Generate narrow browser-boundary types only:

- surface family/kind and mount metadata used by generic runtime;
- existing live scope/fragment DTOs where relevant;
- disposable layer names;
- session kinds;
- intent names;
- intent field object shapes, with persisted form fields represented as strings;
- conflict-policy DTOs for apply/defer/cancel behavior;
- any generated constants/helpers needed to avoid hand-written canonical `data-bepis-*`, layer, or intent strings in TypeScript.

Do not generate broad database models or move domain authority into TypeScript. Keep Haskell as the canonical contract source and TypeScript as the consumer. Update tests so the generated contracts are imported by at least one frontend test or compile-time smoke module.

## Acceptance Criteria

- Generated TypeScript includes interaction contract unions/DTOs derived from Haskell declarations.
- `bash ./bin/in-env frontend-contracts` regenerates the expected file.
- `bash ./bin/in-env frontend-contracts-check` passes with no drift.
- `bash ./bin/in-env frontend-check` passes.
- At least one TypeScript smoke test/import consumes the generated interaction contracts.
- Docs state that TS must not define canonical interaction strings by hand.
