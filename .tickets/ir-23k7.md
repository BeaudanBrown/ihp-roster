# Remeasure and split admin/Xero controller-view boundaries

Recheck current admin/Xero file shape and extract narrow data/view/controller boundaries.

## Design

Current measured hotspot from the 2026-04-30 scan:

- `Web/Controller/Admin/Xero.hs` is about 1.9k lines and still mixes OAuth
  connect/disconnect, tenant sync, staff mappings, earnings mappings, pay item
  creation/update, payroll calendar handling, readiness, fragment responses,
  and toasts.
- `Web/View/Admin/Xero.hs` is about 700 lines and renders multiple independent
  sections from one module.
- Supporting Xero modules have grown enough to justify clear ownership:
  `Application/Helper/Xero.hs`, `Application/Helper/XeroPayItems.hs`, and
  `Application/Helper/XeroTimesheetReadiness.hs`.

Target shape:

- Keep route/action types stable in `Web/Types.hs`, `Web/Routes.hs`, and
  `Web/FrontController.hs`.
- Keep `Web.Controller.Admin.Xero` as a thin orchestration layer that checks
  venue authority, calls service/read-model helpers, and chooses the response.
- Extract read-model/query loading first (`ir-fv82`) so all view and mutation
  paths share one data shape.
- Split Xero admin rendering by section second (`ir-8yyg`) while preserving all
  DOM ids, `hx-*` attributes, live-surface metadata, and toast mount targets.
- Move mutation orchestration behind narrow service functions (`ir-ugzm`) so
  action bodies no longer hand-roll Xero API/query/update/response sequences.

Suggested module names are intentionally provisional; match nearby conventions
when implementing:

- `Application.Xero.Admin.ReadModel`
- `Application.Xero.Admin.Connection`
- `Application.Xero.Admin.StaffMappings`
- `Application.Xero.Admin.EarningsMappings`
- `Application.Xero.Admin.PayItems`
- `Application.Xero.Admin.Calendars`
- `Application.Xero.Admin.Readiness`
- `Web.View.Admin.Xero.Connection`
- `Web.View.Admin.Xero.Mappings`
- `Web.View.Admin.Xero.PayItems`
- `Web.View.Admin.Xero.Readiness`

## Acceptance Criteria

- The Xero admin controller action bodies are readable orchestration, not
  multi-concern scripts.
- Xero admin page/fragment loading flows through named read-model records
  instead of repeated query bundles.
- Normal and HTMX/OOB responses render the same section ids before and after
  extraction.
- Existing Xero admin Hspec and Playwright coverage still passes; add focused
  coverage for any extracted pure mapping/readiness logic that was previously
  only exercised through controller tests.
